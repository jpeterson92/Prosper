# Financial/application core boundary

[api_contracts.py](api_contracts.py) and [import_api.py](import_api.py) project the existing services into closed synthetic HTTP contracts without recomputing financial values. [local_api.py](local_api.py) retains ownership of the loopback socket, host/origin/session guard and bounded body reception; import routes and actual OpenAPI are installed only with an explicit guarded synthetic runtime. [T003.4.2 evidence](../../docs/tasks/T003.4.2-import-api.md) owns observed qualification and unrun checks. Original raw bytes and storage paths are not response fields; parsed source, source value metadata and inspection/readiness have distinct meanings. Browser/client generation remains future work.

T003.1 supplies an importable typed package and pinned Python development baseline. T003.2 adds [exact.py](exact.py): bounded decimal strings, original text/quantum, explicit unknowns, precision-80 arithmetic and synthetic diagnostic allocation. See [task evidence](../../docs/tasks/T003.2-exact-values.md) for numeric semantics, tests and limits, and the [development guide](../../docs/engineering/DEVELOPMENT.md) for exercised commands. T004.1.1 adds [bundle.py](bundle.py) and [bundle_schema.py](bundle_schema.py) for strict in-memory synthetic parsing, immutable evidence and raw/normalized fingerprints; [execution evidence](../../docs/tasks/T004.1.1-synthetic-bundle-parsing.md) describes the supported boundary. [checkpoint.py](checkpoint.py) implements in-memory synthetic inspection and comparison; [execution evidence](../../docs/tasks/T004.1.2-checkpoint-reconciliation.md) records limits. Local synthetic transactional import is now implemented as described below; the tax engine and investor application remain unimplemented.

The adopted boundaries are portfolio/lot state, tax screening, risk, portfolio planning, independent validation, application use cases and adapters. See [architecture](../../docs/architecture/ARCHITECTURE.md). Create modules as authorized vertical slices need them; do not prepopulate empty classes or stub behavior.

The [foundation child plan](../../docs/tasks/T003-T004-foundation-plan.md) sequences exact values, canonical checkpoints and import/reconciliation behavior using synthetic data. Follow STATUS's one next candidate; do not jump directly to brokerage APIs or an unreviewed optimizer.

[recovery.py](recovery.py) adds consistent SQLite/evidence backup, a closed versioned application manifest and verified restore to a new isolated runtime. It checks every checkpoint/preview/receipt and active history before publication; interrupted restore markers prevent opening partial state. [Recovery evidence](../../docs/tasks/T004.3.1-backup-restore.md) records the bounded result. T004.3.2 supplies the bounded inspection/recovery workflows below; this does not qualify investor installation or financial use.

[inspection.py](inspection.py) adds bounded diagnostic inspection of runtime, backup and interrupted-restore artifacts, using existing adapters without initialization and one read-only SQLite snapshot. It distinguishes verified required evidence, unreferenced objects/staging, local publication aliases and unresolved facts without repair or cleanup. [Inspection evidence](../../docs/tasks/T004.3.2.1-inspection.md) records exact-state, process interruption, alias/path, hot-journal and WAL checks. A report is never mutation permission; the coordinator below revalidates every action.

[maintenance.py](maintenance.py) adds guarded alias recovery and canonical orphan cleanup under the existing SQLite writer transaction, with complete-state proof and last-action reference/path/identity/hash checks. Unbound staging and unknown/corrupt states are preserved. Explicit compatible-backup recovery targets a new separate runtime; no marker or financial fact is repaired in place. [Execution evidence](../../docs/tasks/T004.3.2.2-guarded-recovery.md) records interruption, competing writers/direct publishers, exact-state and installed qualification. Investor/release qualification remains separate.

[evidence.py](evidence.py) adds versioned immutable input-file publication, verified bounded retrieval and explicit synthetic/private runtime boundaries. Its receipt records raw-byte identity, length and adapter-controlled relative reference; it is not an import commit. [Evidence-storage qualification](../../docs/tasks/T003.3.1-immutable-evidence.md) records Windows alias/publication tests and interruption limits. [persistence.py](persistence.py) stores exact immutable checkpoint versions in SQLite and reconstructs verified inspection from original evidence; [task evidence](../../docs/tasks/T003.3.2-sqlite-checkpoints.md) records scope and checks. The bounded foundation recovery workflow is described above; investor storage installation remains unimplemented. [previews.py](previews.py) supplies durable preview/rejection, and [imports.py](imports.py) supplies atomic activation/current generation, historical source conflicts and durable scoped command outcomes. [Activation evidence](../../docs/tasks/T004.2.2-atomic-activation.md) records schema-three upgrade, real rollback/restart and competing-writer checks. Stored inventory, active state and historical receipts have distinct meanings; planning readiness remains false.
