# Verification suites

`test_bootstrap.py` contains four locally exercised toolchain qualification tests: editable package import from an unrelated working directory, negative Ruff/type-check probes and positive/negative pytest/Hypothesis execution. They create synthetic probe files in fresh ignored project-local scratch directories when run through the helper and validate no financial behavior. Use the [development guide](../docs/engineering/DEVELOPMENT.md) and `scripts/dev.ps1 -Command check`; no empty test collection is treated as passing.

The [validation plan](../docs/engineering/VALIDATION.md) and [written reference portfolio](../docs/domain/REFERENCE_PORTFOLIO.md) still define unimplemented financial/application expectations.

`test_inspection.py` adds 52 T004.3.2.1 cases for immutable diagnostic reports, complete schema-three reference/receipt/history reconstruction, exact F001/source quantum and unknowns, unchanged payloads, orphan/staging classification, local/external aliases, corrupt/missing/incompatible databases and manifests, read bounds, unsafe entries/symlinks/Windows junctions, failed initialization, actual original/backup/restore process exits, refusal to roll back a hot journal, clean WAL repeatability and concurrent WAL changes. [Execution evidence](../docs/tasks/T004.3.2.1-inspection.md) distinguishes observed inspection from unimplemented cleanup/repair.

`test_recovery.py` exercises T004.3.1 application backup/isolated restore: exact F001 values and source quantum, explicit unknowns, inactive checkpoints, all preview states, original command retries, rollback-journal/WAL snapshots with concurrent process mutations, complete required references, incompatible/corrupt/aliased files and manifests, relational corruption despite updated file hashes, resource/path bounds, private-mode separation using synthetic scratch, real abrupt process exits and retained non-ready partial destinations. [Task evidence](../docs/tasks/T004.3.1-backup-restore.md) records checks and installed-wheel qualification. General orphan cleanup/interrupted-original-state recovery, financial correctness and independent acceptance remain unqualified.

`test_exact.py` exercises T003.2 parsing, source preservation, sign/precision rejection, explicit unknowns, exact arithmetic, ambient-context isolation and synthetic diagnostic allocations. Independent integer/Fraction expectations cover ties, fractional/extreme inputs, residual conservation and the 0.33/0.34/0.33 example. These checks cover V45's primitive example and limited portions of V25/V37; complete persistence/transport, fee/tax accounting and qualified broker allocation remain untested. [Task evidence](../docs/tasks/T003.2-exact-values.md) records actual results and limitations.

Introduce suites during authorized implementation for source-linked golden cases, domain behavior, invariants, adapter contracts, independent plan feasibility and complete workflows. Keep fixtures synthetic. Separate tax diagnostic cases from capabilities supported by the planner. Do not report tests, CI or financial correctness as verified merely because these directories exist.

`test_bundle.py` adds 82 synthetic parser cases: strict shape/scalars, value/reason facts, malformed/resource rejection, duplicate keys/IDs, immutability and identity. Two deterministic property tests cover record/key/whitespace permutations and arbitrary bytes. F002/F003/F004/F009 can be structurally parsed while explicitly unvalidated; this suite does not qualify their financial reconciliation/readiness behavior. See [T004.1.1 evidence](../docs/tasks/T004.1.1-synthetic-bundle-parsing.md).

`test_checkpoint.py` exercises independent F000/F001 expectations and incomplete/contradictory references, inclusion, history, quantities, cash, valuation and coverage. Property cases vary quantities/marks and ordering. See [execution evidence](../docs/tasks/T004.1.2-checkpoint-reconciliation.md); this does not qualify broker/tax correctness or import mutation.

`test_previews.py` adds 41 durable-preview/upgrade cases: independent F001 totals, malformed/incomplete/contradictory review evidence, raw-versus-normalized identity, terminal reject/reopen, missing/corrupt evidence, real stage/reject rollback, version-one row preservation, failed/abruptly interrupted schema upgrade and strict metadata/lifecycle guards. Existing persistence cases now expect schema three and still verify checkpoint row encoding/immutability. [T004.2.1 evidence](../docs/tasks/T004.2.1-durable-previews.md) records checks and installed-process qualification. These preview cases do not alone qualify active switching or receipts; full recovery and tax correctness remain unqualified.

`test_imports.py` adds 48 atomic-import cases: independent F001 totals, F002-F009 variants, incomplete-fact activation, historical event/snapshot conflicts, identity boundaries, original-outcome retries, stale/duplicate ordering, real SQL rollback, abrupt process exit/restart, competing-process distinct/same/colliding keys, evidence/relational corruption and schema-two upgrade rollback/interruption. See [T004.2.2 evidence](../docs/tasks/T004.2.2-atomic-activation.md). Independent financial/software review and release are separate gates.
