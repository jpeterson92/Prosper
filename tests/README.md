# Verification suites

Use `scripts/dev.ps1 -Command dev` for affected development checks, or explicit `-TestPath` filters for cold/stale baselines. Default Python workers are `auto`; `-Workers 0` enables serial debugging. Full checkpoints belong to deliberate commit/sync boundaries. [Development](../docs/engineering/DEVELOPMENT.md) owns commands; [STATUS](../docs/STATUS.md) owns actual results and limits.

- `test_advisory_store.py`, `test_advisory_recovery.py`, `test_import_api.py` and `test_local_api.py` cover current normalized records, source bytes/unknowns, selected settings, immutable/stale runs, durable retries, actual process death/contention, current-schema backup/restore and protected real HTTP processes.
- `test_history.py` covers ordered Polars alignment and independently derived returns; missing leading/interior/tail cells, new/manual names, predecessor/overlap, context/vintage/action refusals, full-window revalidation, saved run-owned sources, explicit cache clearing, corruption and killed/concurrent writers. `test_storage.py` retains generic path/privacy-boundary checks after proof-store removal.
- `test_advisory.py`, `test_basket.py`, `test_industry.py`, `test_equity_benchmark.py`, `test_benchmark_tables.py` and `test_vanguard.py` exercise the current Float64 analytical/source path. Original source text, complete row accounting, unknowns, order/cardinality, explicit selected cash, no tolerance waiver, underflow, source/identity/linkage refusals and independent exposure/covariance expectations remain. Old exact-result/ratio-wire and full-fund denominator APIs are retired.
- Innovation, volatility, shrinkage, DCC and covariance suites retain their selected equations, independent/reference expectations and component refusal cases. Software tests do not establish independent model review, calibration or qualified real inputs.
- Fidelity/source-shaped lot and assembly suites retain fictional source/numerical qualification cases for the upcoming lot workflow. They do not establish current application lot integration or actual broker/account applicability.
- `test_project_checks.py` covers current text/link checks without a hash manifest. `test_test_workflow.py` checks selection/failure/cache/isolation on miniature fictional projects. `test_bootstrap.py` qualifies the project toolchain without treating an empty test collection as passing.

Browser workflow/security checks live in [frontend/tests](../frontend/tests). Current history tests exercise reviewed manual refresh, identical lost-response retries, saved inputs through cache loss/current recovery, scoped failures and desktop/narrow layouts. Traces/video are disabled; all fixtures/screenshots/runtime artifacts are fictional and local. The [validation plan](../docs/engineering/VALIDATION.md) retains separate software, source, model, tax, observed-user and release acceptance.
