It is a local Python reference request, not a browser upload or fitted investor model. All names, account roles, evidence and selected limits are fictional.

FAAA has 2.5000 shares, total basis USD 30 and mark USD 10. FBBB is an eligible replacement at USD 10. Selected additional cash and costs are explicitly zero. Benchmark weights are 50/50; annual covariance is diagonal 0.04/0.09; selected annual TE cap is 0.10. Sale bounds are 0..2 whole shares from `lot-a`, buy bounds 0..2 FBBB shares, producing nine states. These bounds and limits are reference inputs, not investor defaults or a production workload.

From the repository root with the project interpreter:

```python
from pathlib import Path
from prosper.candidate_records import CandidateRequest
from prosper.candidate_reference import search

request = CandidateRequest.model_validate_json(
    Path("examples/synthetic/candidates/tiny-request.json").read_bytes()
)
result = search(request)
assert result.best is not None
print(result.best.metrics)
```

The result includes a frozen copy of the request, checked baseline/best orders, complete/stopped domain counts, unresolved-state count, exclusions and persistent qualification warnings. JSON can be reopened through `CandidateSearch.model_validate_json` without running search or financial analytics. This is record serialization; current application save/recovery integration belongs to T007.1.2.

`max_states` bounds work; an optional `should_stop` callback can cancel between states. A stopped or unresolved search reports an incumbent/no candidate, not an optimum or proof of infeasibility. A completed, fully decided tiny domain can report its own optimum or absence of a feasible positive-loss harvest. There is no claim outside the declared domain. Numerical failure stays explicit.

Costs apply one selling fee per security/side order, including multi-lot sales, and one entered buying fee per security order; mark-to-indicative spread costs are separate. Turnover is gross reference-value sales plus purchases divided by opening stock-sleeve value plus selected additional cash. Final cash/NAV, risk and all enabled controls are independently checked from final orders. Imported cash is preserved outside that selected budget. These are disclosed synthetic fee/funding assumptions, not broker behavior.

Python loops handle the at-most-sixteen discrete dimensions and Decimal final boundary checks; NumPy handles covariance arithmetic. This tiny reference does not need tabular processing or a new solver. The selected production risk model, realistic search capacity/method, independent tax/model acceptance and financial-use/release authority remain separate.
