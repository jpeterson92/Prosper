# Complete fictional modeled inputs

These files exercise the full held/benchmark/candidate union in the current protected local workspace. Every observation, mapping, mark, taxonomy, permission assertion and investor setting is fictional. Input coverage is software evidence; it does not establish a usable risk fit, qualified real inputs or financial use.

Use a schema-3 scoped synthetic runtime and the [local launcher](../../../docs/engineering/DEVELOPMENT.md#local-browser-workflow).

1. Import and select `../advisory-workspace.json`. It contains a 12.5000-share lot and the same independent position; those are one held exposure. Unknown original classification remains in the snapshot and is resolved only for this synthetic input view by the explicit reviewed mapping below.
2. Follow the [benchmark walkthrough](../benchmark/README.md), save the fictional benchmark result and explicitly select it.
3. Load `lot-settings.json` under **Explicit lot settings JSON**, review it and save it. Costs, selected additional cash, funding and final-cash settings remain separate from imported account balances. This file supplies the same mark for the held security as the complete input bundle.
4. Load `history.json` under **Fictional history response**, review it and refresh. It supplies all five names over the predecessor and three required sessions. Provider symbols, dated canonical mappings, USD/calendar/action/adjustment conventions and source bytes are explicit. It is never a live acquisition or a production provider choice.
5. Load `current.json` under **Modeled input/profile JSON**. Review the profile, investor controls, original-source digests, complete union and blockers. Acknowledge the review and save the dated input diagnostic. **Recheck current modeled inputs** reads current history/settings without rewriting an earlier result. A stale reviewed revision is refused.
6. Reopen the saved diagnostic, clear reusable history cache if desired, and download/restore a current workspace backup into an empty schema-3 runtime. The saved grid, exact supplied settings, original required sources and output remain available without recalculation. Source corruption blocks a complete backup while saved output stays readable.

The first two are benchmark names, `security-a` is held, and the last two are explicitly requested candidates. No retained name is dropped to make coverage pass, including zero weights, fractional holdings or missing classifications. Only explicitly known unsupported held classes are excluded, with locators/reasons. An excluded held name cannot reenter as a conflicting candidate mapping. A separate test retains 603 required names with located missing coverage; it is not a qualified workload or proof of a fitted model at that size.

No provider, taxonomy license or production profile is adopted by these examples.
