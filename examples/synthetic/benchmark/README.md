# Fictional benchmark workflow

These offline examples contain fictional holdings and review assertions. VTI's request registry identity is used to exercise the standard picker; the holdings are not actual VTI constituents. Nothing here qualifies financial use, source identity or a real benchmark.

Start a fresh scoped runtime, for example `.local/benchmark-demo`, using the [local launcher](../../../docs/engineering/DEVELOPMENT.md#local-browser-workflow). Stage/select `../advisory-workspace.json` first so the saved benchmark review belongs to a current workspace run.

1. Expand **Import saved benchmark response** and load `current-observation.json`. This records the historical request for January 3, 2000, collected January 4. It never contacts a provider or falls back after a failed public request.
2. Read the original response, then load `current-review.json` under **Reviewed benchmark mapping and metadata JSON**. Review its independent fictional metadata attachment, ticker/fund/CUSIP/date, explicit primary/empty section roles, every include/exclude reason and mapped security. The supplied review rules include original row identities and attributable dated evidence; a ticker alone does not establish eligibility. Real reviews need retained actual metadata and qualified mappings/relationships for the exact captured source.
3. Check the review acknowledgement and save the reviewed result. Acquisition and saving do not select a benchmark. Then use **Select this reviewed benchmark**. Later settings/imports cannot rewrite that saved output.
4. Reopen it using **Saved diagnostic**. Download a current workspace backup and restore it into an empty current workspace to preserve original holdings, metadata, selection, review inputs and output without recalculation.

The eight original rows yield two retained mapped equities with values `60.00` and `30.000`. Their denominator is **E = 90**, and derived Float64 weights are approximately **2/3** and **1/3**. The first published percentage is the number token `60.0000`; the second is an original blank string. Neither is normalized or replaced. Six exclusions retain reasons, **10 USD** of known signed source values and **one unknown excluded value**. Exclusions do not create cash. Fractional Float64 display differences in the final bit are calculation estimates, not supplied exact amounts.

Unknown/missing included values, stale identities, incomplete rows or ambiguous alternate links produce an incomplete saved review with no selectable weights. Failed acquisition, wrong fund/date, duplicate JSON keys, changed schema, empty data, throttling, redirects and incomplete responses never select another fund/date/source. Public requests are explicit bounded backend GETs for VTI or VOO only. A lost response retries its original observation ID; an interrupted reserved attempt remains pending and needs a new explicitly requested attempt rather than automatic reacquisition.

Current schema **11** includes benchmark observations. Earlier internal schema 1/2 advisory stores and checkpoint stores/backups are unsupported. Choose a new scoped directory and reimport fictional inputs; no migration or automatic deletion occurs. Ordinary uploads retain the 2 MiB envelope limit; benchmark review/import envelopes allow 16 MiB for complete rows plus metadata, retained source BLOBs allow 16 MiB each, and backups allow 64 MiB. All source arrays remain in original bytes; no top-500 limit is applied.
