# Data-contract framework

Current advisory records contract. These are requirements for the current normalized workflow; [STATUS](../STATUS.md) records actual integration/recovery evidence. The [numerical contract](../engineering/ADVISORY_NUMERICS.md) owns representations/tolerances. No previous internal API/schema/reader/backup must remain compatible.

## Shared conventions

Use the minimum records needed to import a current snapshot, calculate estimates and save/explain a suggestion. Preserve original sources once, material values/units, stable account/security/lot references and useful row locators. Unknown is null with a reason, never zero. Numeric spellings need not remain distinct after normalization; original files remain available. Missing classification or basis blocks its dependent result, not unrelated diagnostics. Tickers alone do not establish identity.

Source as-of and import time are distinct. Keep dates/timezones where meaningful; a trading date is not an invented timestamp. No general bitemporal/event-ledger framework is required. Retain sources privately outside source control; hashes identify files and do not anonymize them.

SQLite is the single authority for current import/run records. Store supplied quantities/basis/entered exact amounts as decimal text and derived estimates as finite numerical values under the numerical contract. Current records include `advisory-import-v1`, `advisory-analysis-v1` and typed `manual-worksheet-v1`. Schema 13 retains current immutable worksheets and recoverable pending history parts, and uses bounded original-source and history encodings described below. Version labels identify the chosen current format and permit clear unsupported-format errors; they do not require older readers, schema migrations, export bridges or old-backup support. Breaking development changes may use an explicitly scoped fresh runtime/reimport. No exact source-code hash defines the data contract, and unsupported state must never become a silently repaired/empty portfolio.

## Records

Installed launch uses one chosen workspace outside replaceable app files, with deliberate initialize/start and no mode marker or source-checkout dependency. The protected `/runtime` response describes exploratory operation and unavailable financial authorization without filesystem paths or data categories. Current-format backup/restore preserves original records/sources; opening missing/corrupt/unsupported state never silently resets user work. [The launch guide](../guides/LOCAL_ARTIFACT.md) owns the simple local workflow.

These are logical responsibilities, not a requirement for a table/class per row. API DTOs may expose safe subsets. Pydantic checks shape, Polars handles tables and explicit domain checks handle material eligibility/financial conditions; avoid repeating the same checks at every layer.

## Holdings-first assembly and selected cash

Current lot/holding snapshots establish the starting state. Attributable supplemental facts can resolve specific unknowns. Missing history permits conditional screening with explicit warnings/manual restrictions under D038; known conflicts and required basis/identity/risk facts retain their scoped blockers. Compare independent positions if supplied; do not demand a redundant export or assume a sum of lots independently proves source completeness.

Keep imported cash (optional), selected additional-cash budget and optional final-cash target separate. Compute stock-sleeve-plus-selected-cash baseline/final weights; untouched balances remain outside the modeled sleeve. D045 benchmark retained equities sum approximately to one under the numerical contract. Final cash/quantities are recomputed after costs and discrete choices.

## Snapshot and event reconciliation

V1 replaces selected current snapshots transactionally rather than reconstructing accounts from fills/events. Imported activity is screening information, not an instruction to add holdings already represented in the opening snapshot. Source cutoff uncertainty is reported where it affects a calculation; no fabricated same-day sequence or full account reconciliation is required to display a holding.

Correct a source value through a new import/reviewed observation while preserving saved outputs and original sources. Do not infer broker lot allocation, add a wash adjustment twice, or merge lots merely because date/ticker/price match. Actual-fill reconciliation, order status, basis maintenance and forward monitoring are deferred under D046. After external trading, require a fresh holdings/lot snapshot for another suggestion.

## Time semantics

Retain source as-of, import time, analysis as-of and relevant activity/restriction dates. Keep reference quote and historical-window dates visible. A fresh download of an old report is still old economic data. Scope/date assumptions affecting screening must be explicit, including cross-year periods where applicable. Current-format stored estimates remain readable during normal use; freshness affects their reuse. D047 permits format-breaking development changes with a documented scoped fresh runtime/reimport instead of migration.

## Generic import bundle

New advisory import shape is `advisory-import-v1` above. Selected-source adapters normalize supported spellings/notation and preserve original bytes; source/row-size and finite/magnitude checks remain. Unknowns, duplicate/ambiguous lot/security mapping and required missing fields have located explanations. Every input uses the same contracts. Fictitious accounts/market data are test fixtures and are not categorized by the app. The current API and generated TypeScript use these normalized records.

The old `synthetic-checkpoint-v1` transport is a superseded development implementation; its specification is recoverable from the pre-compaction Git checkpoint. There is no requirement to read/map/export it or retain its validators after current consumers are updated. [T019](../tasks/T019-advisory-remediation.md) integrates the current workspace/recovery and replaces history/assembly paths while removing obsolete machinery.
