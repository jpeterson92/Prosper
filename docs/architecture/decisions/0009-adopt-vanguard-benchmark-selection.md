## Context and decision

The [Vanguard investigation](../../tasks/T017.1-vanguard-api-investigation.md#follow-up-dated-full-portfolios-and-owner-source-clarification) found public advisor full-portfolio latest/historical JSON endpoints. The owner clarified that the intended index approximation is the ETF's complete portfolio and explicitly rejected creation/redemption baskets. Subsequent requests selected the Vanguard route as the standard. File-only entry and the old supplied-workbook default are superseded; requiring manual uploads for ordinary selection is no longer the product assumption.

- **Standard route:** users select a supported Vanguard ETF and an actual reported holdings date. No particular ETF is preselected on the owner's behalf. Fetch the issuer's full-portfolio response through Prosper's local backend. The observed `latest` and `historical?effectiveDate=YYYY-MM-DD` advisor endpoints are the initial adapter targets. The initial implemented request list contains VTI and VOO only; expansion needs source/identity/schema/scale evidence, not an assumption of universal support.
- **Source meaning:** use a disclosed ETF-holdings benchmark proxy, not an exact index constituent feed. **Creation/redemption/PCF baskets are forbidden benchmark inputs and fallbacks.** A portal catalog may inform discovery but cannot qualify complete portfolio contents. Initial static request identifiers are sufficient for the bounded adapter; broad catalog/name discovery remains future qualification.
- **Dates and collection:** use the latest response to learn the actual latest reported date, then offer reporting-date choices and explicit historical requests. Display requested, effective and collected dates separately. Validate the returned date and retain HTTP errors/empty results. No automatic substitution of latest, a neighboring date, upload data or a basket when the requested date is unavailable. Historical as-of access does not establish initial publication time or absence of look-ahead.
- **Evidence and versions:** preserve exact response bytes/number tokens, source URL, request fund/portfolio identity, adapter/schema identity, collection timestamp and all sections/rows. A source URL alone is not independent fund-identity verification; qualify identity against official fund metadata before canonical activation. Reconcile alternate/duplicated sections, all economic exposures, unknown weights and identifiers. Do not concatenate arrays, discard CVRs/unsupported holdings, truncate to 500 rows, infer cash, silently repair values or renormalize. The owner has not selected a residual, cash or derivative transformation.
- **Review and refresh:** acquisition yields observations, not an activated benchmark. Preview source/proxy/date, full counts, unknowns, reconciliation and applicable capacity/freshness findings before activation. Freeze an immutable selected version for each run; later refreshes create new reviewable versions and preserve earlier results. Request-triggered acquisition is distinct from optional market-history scheduling, which remains Off / Never under D040.
- **Secondary routes:** retain explicit manual/custom benchmark uploads, including qualified issuer files. The old workbook remains an optional local reference; it no longer defines the default route. Automated tests/examples remain fictional and offline by default. Do not silently use an upload when Vanguard acquisition fails.
- **Permission and other data:** rely on the owner's already stated Vanguard noncommercial permission; no repeated authorization is needed for this scoped public source work. Benchmark holdings/marks do not replace qualified risk histories, execution quotes, security/tax classification or independent model acceptance. No paid commitment, private portfolio access, deployment, publication or financial-use approval follows.

## Implementation and acceptance

[T006.1.7](../../tasks/T006.1.7-vanguard-acquisition.md) owns the standalone acquisition/observation component. [T006.1.1/.8/.9](../../tasks/REMAINING_WORK_PLAN.md#t0061-decomposition) own exact benchmark consumption, full-response reconciliation/frozen activation and the local API/browser picker. The source default is selected now; the current synthetic import browser does not yet have a benchmark screen. Existing live work and its exact-input prerequisite remain in sequence.

Required evidence includes latest/reported-date requests; explicit fund selection; exact lexemes and every section/row; missing, duplicate, contradictory and non-unit facts; HTTP 204/404/429/5xx, wrong fund/date, redirects, schema changes, interrupted responses and no fallback; source and canonical identities kept separate; version/restart/offline replay; unknown/unqualified inputs blocking dependent risk use; explicit custom-file selection; and browser default/refresh/activation behavior against synthetic responses. Same-agent engineering tests do not establish source completeness, supported scale, financial acceptance, model review or release.

Reconsider on issuer route/schema changes, insufficient full-portfolio coverage/freshness, fund-identity ambiguity or owner direction. A failure does not authorize a basket fallback or financial transformation.
