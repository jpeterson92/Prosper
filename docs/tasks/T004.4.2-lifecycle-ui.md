## Behavior and acceptance

The existing review screen now requires an explicit acknowledgment of the selected preview, readiness reasons and separately read current checkpoint before new commit/reject actions. A new command uses a fresh key, the selected original-byte digest and the last read safe-integer generation. Inspection-invalid or rejected previews cannot be activated through the normal control. Incomplete basis/coverage remains eligible only for inspection-valid storage under existing backend semantics; planning stays unavailable. Rejection is terminal for original bytes, preserves evidence, and cannot undo a committed checkpoint. There is no financial override, correction acceptance, account switch or trade-approval control.

The last-command panel keeps the frozen key/digest/expected-generation descriptor and the backend's original durable receipt, including observed/original activation generations and recorded time. Present state is read separately after a known receipt. Stale results clear the review acknowledgment and require new review against a fresh generation; retrying that old command returns its original stale outcome. Historical duplicates never reactivate old evidence. Source conflicts, identity refusal and concurrently rejected previews show explicit durable outcomes.

Writes are never automatically retried. Lost responses retain the original command descriptor or rejection digest and block a replacement lifecycle decision. Explicit retry sends the same payload; a new session can be acquired after refusal/restart. Before reload, users must retain the displayed command key/digest/original expected generation; after retrieving that preview, **Resume a commit after reload** explicitly retries those details. If the original request never reached the runtime, this explicit retry may execute it now. No browser persistence or session/token storage is introduced. A same-key/different-payload HTTP 409 is a refusal, with correction of recovery details/new review available in the same page. A known receipt survives failed follow-up reads and current state becomes unavailable. A rejected-commit race cannot change active state; fresh reads resolve a refused/uncertain rejection.
