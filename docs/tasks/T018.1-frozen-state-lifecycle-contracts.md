## Frozen analysis input and invalidation contract

This is a semantic checklist for later owners, not a serialized schema. Reference immutable evidence/versions rather than copying mutable browser values or logging portfolio payloads. One consistent accepted state is read before computation; optimization must not hold a database writer transaction open. The worker receives facts/settings and returns evidence only. Application services retain all publication, approval and reservation authority.

Import generation alone cannot detect a cash-budget edit, changed manual restriction, refreshed risk model or restored/forked runtime with the same generation number. T007.2 must compare all relevant frozen references on publication, and T008.1 must do so again atomically with approval/reservation. A conservative full-bundle comparison is sufficient until a narrower dependency comparison is justified. Old-runtime/session worker responses cannot be accepted into a restored process merely because an integer generation matches. Exact token encoding and restart fencing belong to those implementations and T018.2; this report installs no runtime epoch or new persistence format.

Changes create new input/run/candidate versions and leave prior known-at-review evidence reproducible. A late backdated correction uses its economic time and later recorded time; it does not rewrite earlier knowledge. Rejection/revision cannot mutate approved quantities in place. Relevant data/settings changes or elapsed configured freshness make dependent recommendations non-actionable; actual execution evidence remains admissible for reconciliation. Quote/plan expiry settings require D017 evidence: no minutes, dates, investor caps or timezone conventions are invented here. Missing expiry configuration blocks the dependent actionable operation until qualified.

Under D038-D039, missing broker history or an explicitly empty manual list stays **unverified**, not clean; retain the warning through conditional results, review and worksheets. A resolved recent name restricts both sale and replacement-buy legs, while known imported conflicts cannot be cleared by omission. Unknown term alone does not invent ST/LT or universally block an otherwise supported unweighted ordinary loss calculation. Basis/identity contradictions, required risk gaps and invalid funding remain scoped blockers; block the account if impact cannot be bounded.

Unset additional cash is visibly reviewed as zero; it never converts unknown imported cash to zero. Changing selected cash requires a new frozen run even with unchanged import generation. The budget is a cap, not a spending target. Baseline risk scope is included stock value plus selected cash; final scope includes residual cash/costs and preserves untouched account cash outside that scope. No selected assumption alone proves usable buying power.

## Review findings and disposition

1. **Import generation is a narrow counter.** It omits future non-import edits and is reproduced from backup; frozen input identity and runtime/session fencing must accompany it. Assigned to T007.2/T008.1/T018.2 above; no schema is added.
2. **Corrections are not yet a supported transition.** Existing immutable history/conflict refusals protect prior evidence, but cannot claim known-at-approval correction propagation. Assigned to T002.2/T009.1 with dependent invalidation/review owners; do not bypass a conflict by inventing an identity.
3. **Conceptual result/readiness names are not implemented transport values.** Preserve current closed APIs and false planning readiness. Conditional history/cash semantics belong to assembled input and financial tasks, rather than weakening the legacy synthetic parser.
4. **Recovery has only the evidence it currently owns.** Existing raw-file completeness is qualified; future frozen risk/plan/commitment evidence and post-backup external divergence require new feature-owned checks. No backup success clears execution uncertainty.
