## Observed catalog and basket feed

The [root API](https://etfportal.vanguard.com/extrapi/v2/us/standard/) returned HTTP 200 and XML, not an API documentation page. It contained **183 basket records across 116 distinct tickers**: 116 `CRRD` (Standard), 55 `RDMP` (Redeem Only), and 12 `CRTN` (Create Only). There were no duplicate ticker/usage pairs in this snapshot. This is the observed catalog, not proof of coverage of every Vanguard ETF.

Each `basket` carries `estimatedDate`, `trdDate`, and `navAsOfDate`. Its `profile` provides `basketId`, `bsktHistId`, creation-unit size, currency, fund CUSIP/ISIN, expected holding count, settlement facts and nested `fund` ticker/`portId`. `fund.shortNm` was empty for the sampled funds; user-friendly fund names need another source. The catalog exposes the identifiers needed to construct downloads; it is not a list of explicit downstream hyperlinks.

The observed download pattern is:

```text
https://etfportal.vanguard.com/extrapi/v2/us/standard/{basketId}/{usageCode}/holdings.json
```

The owner's double-slash VOO URL and its single-slash equivalent both returned HTTP 200 with identical saved response content. Downloads succeeded without supplied credentials or an authenticated session. The portal's HTML home redirected to a login page; the public feed was independently accessible. No login was attempted.

| Fund | Basket ID | Usage | Returned rows | Sum of published row weights (%) |
| --- | --- | --- | --- | --- |
| VOO | `01S990737` | CRRD | 503 equity | 99.9932 |
| VTI | `000005306` | CRRD | 1,600 equity | 99.9893 |
| BND | `0000S4333` | CRRD | 121 debt | 99.0253 |

All three initially returned trade date **October 26, 2026**; the catalog's NAV-as-of/estimated dates were **October 23, 2026**. The unparameterized URLs returned the current published basket. The follow-up below establishes date selection, superseding the initial investigation's unresolved historical-access question. A hard-coded unparameterized URL is not a frozen historical benchmark.

The holdings envelope includes `bsktHistId`, `basketId`, `portId`, trade date, category counts and a `holding` array. Sample equity rows include ticker, CUSIP, SEDOL, ISIN, primary exchange, currency, country, name, `sector`, quantity, price, market value, `weighting` and cash-in-lieu/in-kind flags. `weighting` is in percentage points. VTI had five blank tickers and five blank classification labels despite complete CUSIP/ISIN fields in this sample. BND had different row fields and TBA/cash-in-lieu distinctions. ETF basket prices are source valuations, not qualified execution quotes or adjusted risk histories. The field called `sector` contained industry/subindustry-style names; no classification standard, hierarchy or version was qualified.

**Meaning matters:** these are creation/redemption baskets, not established full-portfolio holdings. Vanguard's [current Statement of Additional Information, PDF page 51](https://www.vanguard.com/pub/Pdf/sai072.pdf#page=51) distinguishes PCFs, whose securities may overlap actual/expected fund holdings, from complete portfolio disclosures. The sampled VTI basket has far fewer rows than its full holdings below. Because their dates differ, this is evidence against assuming equivalence, not a same-date tracking-error or missing-weight measurement. A basket can sum near 100% while representing a selected trading basket.

Programmatic downloading is straightforward: fetch the catalog once, retain every basket variant and date, select the desired usage explicitly, then fetch the selected basket. Downloading every variant for every fund is unnecessary for an interactive picker. Only three basket downloads plus VOO's slash-equivalence check were performed; bulk availability, throttling, stability and service guarantees were not tested.

## Fuller portfolio route discovered and tested

Vanguard's public [VTI advisor page](https://advisors.vanguard.com/investments/products/vti/vanguard-total-stock-market-etf) and its served [application module](https://advisors.vanguard.com/investments/products/assets/index-BeOPlgaI.js) expose a separate fund-holdings service. The site's code calls latest, historical, daily and composition routes by `portId`. Its CSV exports are constructed client-side from holdings data; a JSON consumer can avoid that presentation layer's rounded strings and placeholders.

| Request | Observed outcome |
| --- | --- |
| [VTI latest, port 0970](https://advisors.vanguard.com/investments/products/api/funds/0970/holdings/latest) | HTTP 200; `latestEffectiveDate=2026-09-30`; 3,519 equity rows |
| [VOO latest, port 0968](https://advisors.vanguard.com/investments/products/api/funds/0968/holdings/latest) | HTTP 200; `latestEffectiveDate=2026-09-30`; 505 equity rows |
| [VTI August history](https://advisors.vanguard.com/investments/products/api/funds/0970/holdings/historical?effectiveDate=2026-08-31) | HTTP 200; date key `2026-08-31`; 3,507 equity rows |
| [VTI daily](https://advisors.vanguard.com/investments/products/api/funds/0970/holdings/daily) | HTTP 404; do not infer daily full holdings for VTI |

These requests also succeeded without supplied authentication. The working catalog maps VTI to `0970` and VOO to `0968`, providing a bridge from ticker selection to these holdings URLs. Leading zeros must survive parsing. A response to VTI latest with `Origin: http://127.0.0.1:8000` returned `Access-Control-Allow-Origin: *.vanguard.com`, which does not permit that browser origin, and `Cache-Control: Public, max-age=300`. Use Prosper's local backend for outbound acquisition; do not depend on direct browser cross-origin access. Cache headers are not proof of portfolio freshness.

The latest JSON has `latestEffectiveDate` and date-keyed objects containing `equity`, `fixedIncome`, `shortTermReserves`, `shortTermReservesMoneyMarket`, `formattedFundOfFundsHoldings`, `allocationToUnderlyingFunds` and `derivatives`. Equity rows supply `holdingName`, ticker, `percentOfFunds`, classification label, market value, quantity, CUSIP, SEDOL, country and depository-receipt type. ISIN, exchange and currency were absent from the sampled equity rows; those facts cannot simply be copied from a different-date basket without qualified identity matching.

Specific reconciliation findings:

- VTI equity: **88 blank published weights**, 44 blank tickers and 11 blank CUSIPs. Its numeric equity weights sum to **99.67959%**; that is a partial numeric sum, not a completed benchmark.
- VOO equity: **two blank weights**, including CVR entries; numeric equity weights sum to **100.01615%**. One ticker is blank. Unsupported or ambiguous instruments remain visible.
- Reserves and derivatives are separate. VOO's numeric reserves sum is negative (**-0.11872%**). Negative source values are retained, not silently converted to zero.
- `allocationToUnderlyingFunds` exactly duplicated `shortTermReserves` in both latest samples. Other arrays include alternate schemas; for example, `shortTermReservesMoneyMarket` had 3,542 VTI rows and 519 VOO rows without `percentOfFunds`. Concatenating all arrays would not produce a justified portfolio.
- As a diagnostic only, numeric weights in equity + short-term reserves + derivatives total **99.99995% VTI** and **100.00004% VOO**. Blank weights remain unknown. These near-unit sums do not qualify cash treatment, economic derivative exposure or a normalization rule.

The advisor route is the candidate for a full ETF-holdings proxy. Its observed September 30 vintage is substantially older than the basket trade date. The initial August history request established that specific vintage; the follow-up below extends the observed dates. No complete retention window, arbitrary-date coverage, complete-fund support or daily schedule was qualified.

## Follow-up: dated full portfolios and owner source clarification

The owner requested further investigation of date-selectable endpoints, then clarified that the desired approximation is the **ETF's complete contents**, excluding creation/redemption basket composition. This is the governing source requirement for the proposed benchmark integration. The portal basket feed is excluded as a benchmark input or automatic fallback. Its catalog may supply fund identifiers, but catalog availability is not proof of full-holdings coverage. No primary-route implementation or change to the supplied testing default was authorized.

The advisor full-portfolio endpoint accepts **`effectiveDate=YYYY-MM-DD`**:

```text
https://advisors.vanguard.com/investments/products/api/funds/{portId}/holdings/historical?effectiveDate=YYYY-MM-DD
```

Further direct public GETs returned HTTP 200 with the exact requested date as the response's date key:

| Fund / port ID | Requested date | Equity rows returned |
| --- | --- | --- |
| VTI / `0970` | 2026-09-30 | 3,519 |
| VTI / `0970` | 2026-06-30 | 3,531 |
| VTI / `0970` | 2025-09-30 | 3,529 |
| VTI / `0970` | 2024-09-30 | 3,656 |
| VOO / `0968` | 2026-08-31 | 505 |

These supplement the earlier successful VTI August 31, 2026 request (3,507 equity rows). For example, [VTI September 2024](https://advisors.vanguard.com/investments/products/api/funds/0970/holdings/historical?effectiveDate=2024-09-30) supplies a working older full-portfolio request. These are counts of the equity section, not a claim that all economic exposures are equities. Preserve the other sections and unknowns described above. VTI's non-month-end **September 29, 2026** request returned **HTTP 404**; the daily route also returned 404 in the initial investigation. The demonstrated service supports particular reporting snapshots, not arbitrary daily complete portfolios.

The public [equity-holdings component](https://advisors.vanguard.com/investments/products/assets/EquityHoldings-aCgVHV8U.js) constructs its date dropdown by calling a helper with `latestEffectiveDate`, `getInterval` and `getPastIntervals`. The helper in the [main module](https://advisors.vanguard.com/investments/products/assets/index-BeOPlgaI.js) begins with the latest reported date and generates preceding month- or quarter-end dates. Its ordinary index-ETF configuration selects 12 monthly choices. **This is generated UI navigation, not a returned inventory of available vintages or a demonstrated server retention limit.** The working 2024/2025 requests reach beyond the latest 12-month display. No dedicated availability-list endpoint was discovered in the inspected code.

Recommended date flow: fetch `latest` to learn the actual latest reported effective date; offer reporting-date choices and a custom historical-date request; fetch the chosen full portfolio and require the returned date to match. Treat 404/empty/error responses as unavailable and do not replace them silently with another vintage or a basket. If an eventual feature offers the latest available snapshot on/before a requested day, that separate selection rule must disclose the chosen date. Retain collection/publication evidence separately: historical as-of access does not establish when a snapshot first became publicly available or qualify a backtest free of look-ahead.

Before the owner's clarification, a bounded basket follow-up also found `trdDate=MM/DD/YYYY` on the portal catalog and holdings URLs. VOO requests returned different histories for September 30 in 2024/2025/2026 and October 23, 2026, with actual changed holding arrays; a dated VTI basket still contained 1,600 rows. The tested `effectiveDate` basket parameter and generic catalog `date` parameter instead returned current content; ISO `trdDate` returned 404 and a weekend request returned 204/empty. These findings are retained only as source-discovery evidence. They do not qualify the basket for the owner's full-portfolio benchmark requirement, and no further basket investigation is needed for this objective.

## Proposed Prosper integration

Recommend a **Vanguard ETF picker as the primary convenience flow**, subject to an explicit later adoption/implementation request and source qualification. Keep file upload available for custom benchmarks and recovery. Label a selected fund as an ETF-holdings benchmark proxy, preserving the distinction from an exact licensed index constituent feed.

1. Maintain a supported fund list with official name, ticker and `portId`; use catalog discovery as input, not automatic proof that every fund is suitable. Initially qualify a small domestic-equity set. Do not trim a larger fund to 500 rows to fit the existing capacity target.
2. Fetch full holdings through the local backend, validate the returned fund/date/envelope and retain the exact response bytes and original number lexemes. Exclude basket feeds as benchmark inputs or fallbacks. Retry with bounded backoff/cache behavior; no silent fallback between vintages.
3. Present the effective date, collection time, source type, counts, unresolved identities/weights and reconciliation result before activating a frozen benchmark version. Preserve all rows. Explicit treatment of cash, derivatives, CVRs, other unsupported instruments and residuals remains necessary; neither dropping nor renormalizing is selected here.
4. Freeze a content-addressed selected version for each run. A refresh creates a new version requiring review; it must not mutate historical results. Preserve requested/returned dates, source URL, fund/basket identities and schema/acquisition evidence.
5. Test the adapter with authored synthetic responses for unknown weights/identities, duplicate/alternate sections, wrong fund/date, changed schemas, HTTP errors and interrupted refreshes. Qualify mappings, source reconciliation, freshness and universe capacity separately from risk history and model acceptance.

This research supports the convenience flow's feasibility. It does not implement an adapter, select a transformed weight policy, qualify financial use or alter the current execution queue.
