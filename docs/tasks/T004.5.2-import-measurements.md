## Workload validity and method

`scripts/measure_imports.py` generates only fictional data from the adopted F001 schema. The 100 distinct securities each have 20 lots acquired January 2, 2024, no recent activity, explicit closing-checkpoint inclusion and stipulated coverage. For stock index i=1..100, price is 50+i, basis per share is 100+i, and lot j=1..20 has j/4 shares. The separately checked position quantity is 52.50. Source precision is retained; this workload includes fractional holdings but no proposed orders.

The independent standard-library `Fraction` oracle reads the serialized rows without using product parsing, exact arithmetic or inspection. Sum(j)/4 = 52.5 per stock and sum(i)=5050, so quantity is **5250**, basis **790125**, holdings value **527625**, settled/available cash **12345.67**, settled-cash NAV **539970.67** and market-minus-basis **-262500**. Unsettled cash is explicitly zero. The oracle checks per-stock quantities, record counts/references and aggregate totals. Six negative tests perturb basis, quantity, price, cash, lot count and fictional identity. Product inspection must separately match the oracle and remain planning-not-ready. This is engineering workload validation by the same agent, not independent financial review.

The serialized workload is **1,067,516 bytes**, under the existing 2 MiB limit, SHA-256 `45129fff543eddcd53451b417c61bb189da18534e1dfca4be677a5ac84f3d4de`. F001 is **10,085 bytes**, SHA-256 `53ffb3d19bf37e5f454dad966f4569d6e9ec5f9dcbe63aae1bd7ffaf1bf93bde`.

Measurements use `perf_counter_ns` wall time, one first timed call, two untimed warmups and ten recorded repetitions for each phase. The first timed call follows correctness qualification and is **not a cold-start measurement**. GC remains enabled; caches are not cleared; phases run sequentially in one process. No competing qualification command was started until this measurement process finished. Background host load is uncontrolled. p95 is nearest-rank and equals the maximum with ten samples. Parsing and pre-parsed inspection are measured separately and together. Durable new staging includes original-evidence publication, verification and the SQLite preview transaction in a fresh initialized runtime per sample; runtime/schema construction is excluded. Repeated staging uses an existing preview and verifies its unchanged outcome. No checkpoint is activated.

Source/export acquisition, HTTP serialization/transport, browser rendering, runtime startup, manual investor work and installation are excluded. These are local service measurements, not an end-to-end UI latency guarantee, throughput benchmark or capacity certification.
