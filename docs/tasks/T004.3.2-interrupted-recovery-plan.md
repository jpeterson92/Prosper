The existing paired brief described one general recovery state machine. Source inspection now reveals separate observation and mutation contracts:

- [Evidence publication](../../src/prosper/evidence.py) writes a UUID staging file, creates a hard link at the content-addressed object name, then unlinks staging. A failure between link/unlink leaves a known layout whose multiple-link object is deliberately rejected by ordinary `read`. A matching filename alone does not establish that all aliases are local, the bytes match a required receipt, or that unlinking is safe.
- [Checkpoint initialization](../../src/prosper/persistence.py) refuses an existing empty/foreign/incompatible database. Initialization failure, corruption and an unrelated empty file cannot be silently treated as an authorized new portfolio. Snapshot metadata and every required reference must be checked before any action.
- [Restore](../../src/prosper/recovery.py) reserves a new root, records `restore-in-progress`, copies into `restore-work`, publishes evidence, links the database, unlinks its staging name, then clears the marker. The current marker is the constant `isolated-restore-v1`; it contains **no manifest/candidate binding**. Recognizing it does not authorize resuming the directory or clearing the marker. Backup also has a separate manifest-publication boundary.
- Application preview/activation writes publish evidence within a SQLite write transaction, while callers can also publish raw evidence directly through `EvidenceStore`. Therefore an inventory cannot itself authorize later deletion: references, hashes, aliases and paths must be rechecked under the actual mutation boundary. Recovery has to preserve committed evidence through interruption and concurrent attempts, rather than treating file classification as a cleanup capability.

These are observed missing contracts, not runtime failures newly reproduced here. Existing tests explicitly retain interrupted links/work and reject partial state; they do not implement its inspection or cleanup. No new tax/risk/product policy or owner decision is needed to split the engineering work.

**Included scope:**

Unknown, redirected, corrupt or unaccounted-link files are preserved; an interrupted action must not expose a committed reference to missing evidence.

If safe deletion cannot be proved, preservation is the required successful disposition rather than a broader repair.
- Integrate with T004.3.1's complete backup/isolated restore.
