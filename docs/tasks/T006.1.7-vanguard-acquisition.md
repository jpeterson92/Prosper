## Behavior and artifacts

[vanguard.py](../../src/prosper/vanguard.py) defines `DEFAULT_BENCHMARK_SOURCE = "vanguard-full-holdings"`, `select_fund(ticker, effective_date=None)` and `acquire(selection, ...)`. The initial request candidates are **VTI / 0970 and VOO / 0968**. No ticker is selected by default; a supported fund must be explicit. The registry is a bounded starting list, not proof of supported economic universe, all-Vanguard coverage or capacity. `None` requests `latest`; an explicit date uses the advisor historical endpoint and requires that exact date in the response. No startup/import-time request occurs.

The real transport makes one public HTTPS GET with a 30-second timeout, no supplied credentials, an allowlisted fund URL, disabled redirects and a 16 MiB body bound. It does not retry or select a fallback fund/source/date. HTTP 204/404 are unavailable-date outcomes; other non-200 responses remain HTTP failures with retained bounded body evidence. Network failures remain explicit. An interrupted response retains its partial bytes with `body_complete=False`; partial or over-limit data cannot yield a snapshot. There is no scheduling or persistent cache in this component.

Successful structural inspection returns an immutable observation snapshot with UTC collection timestamp, requested fund/URL, returned effective date, raw SHA-256 and an immutable tree preserving JSON strings separately from exact numeric tokens. The acquisition retains the original response bytes. Duplicate JSON keys, nonfinite numbers, malformed/unexpected envelopes, wrong dates, basket signatures and missing/empty equity sections are rejected while response evidence remains available. Bounded depth and row limits are defensive limits, not supported portfolio scale. A changed source spelling changes the raw identity even when its numeric value is the same; no canonical benchmark identity is fabricated.

All source sections and unknown fields/rows remain in the original document. Separate section observations report **partial sums of known published percentage weights**, exact as rational values, and the indexes of missing/invalid weights. They never derive a normalized basket or combine overlapping sections. Negative source weights remain negative with an issue. Blank/numeric-invalid tickers and CUSIPs are located issues; other identity/classification/currency/exchange facts remain unqualified. This is not security resolution or full economic reconciliation.

**Every acquisition/snapshot has `benchmark_ready=False`.** The full-holdings response lacks an independent fund identifier in its envelope, so URL request binding is not described as verified fund identity. Snapshot qualification gaps explicitly retain that fact plus source completeness/reconciliation, classification, cash/derivative/residual treatment, freshness/publication/capacity and missing canonical activation. A structurally sound response with no observation issue is still unqualified. No API/OpenAPI/browser, database schema, financial input or existing import behavior changed.

The adopted policy now defaults to this source route; **a benchmark picker is not yet available in the current synthetic browser**. The old supplied workbook is optional reference, not the default product input assumption. Explicit custom/manual files remain secondary. Creation/redemption baskets are forbidden benchmark inputs/fallbacks. [T006.1.8/.9](REMAINING_WORK_PLAN.md#t0061-decomposition) own complete-response qualification/frozen publication and the local API/browser flow. T006.1.6 requires .8 for standard Vanguard risk inputs; file adapter .2 is no longer a prerequisite for the standard route. Existing numerical .1 and history .3-.5 dependencies remain intact.
