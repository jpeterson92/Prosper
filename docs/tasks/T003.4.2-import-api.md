## Review findings and remediation

- Normal FastAPI validation diagnostics can include supplied input/context. The route handler emits only bounded error codes and safe known locations, with no input excerpts or arbitrary extra-field names. Corrupt-evidence and HTTP validation tests verify absence of payload/path markers.
- Source parser paths can carry oversized imported field names. Projection limits each component to 128 characters and exposes `path_truncated`; a real HTTP case verifies the complete original bytes remain stored.
- Two initial assertions assumed a decoder recursion error and the older `format: binary` schema spelling. The observed decoder safely parsed the bounded wrong-shape JSON, then the strict model returned 422. Actual FastAPI OpenAPI uses string `contentMediaType: application/octet-stream` without base64 encoding. Tests were corrected to those observed contracts; no production change was made to force an outdated schema expectation. The first combined run had 61 passes/two assertion failures; a following 36-case run exposed the transport behavior below. Neither failed run is counted as passing qualification.
- Windows can reset a connection if a client keeps transmitting an oversized body after early refusal. The declared-size test receives 413 before sending/allocating body bytes; full/chunked oversized sender tests accept 413 or the observed reset/broken-pipe disposition and independently assert no evidence/SQL publication and a healthy unchanged current state. This behavior is documented rather than hidden as a guaranteed client-visible JSON error. Mutation transport uncertainty requires the existing same-key retry contract.
- Focused reviewed failure/historical cases passed **3 in 2.60s**; the added streaming/truncation cases passed **2 in 1.67s**. Routine lint/type findings were corrected before final full qualification.
