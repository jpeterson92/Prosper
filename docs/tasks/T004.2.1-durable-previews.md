## Implemented behavior

`prosper.previews.PreviewService` stages original bounded bytes, retrieves reconstructed parser/inspection results and rejects previews terminally. Identical raw repeats preserve original time/identity/state; changed spelling retains separate evidence even when normalized content matches. Malformed/contradictory bounded input remains review evidence and cannot create checkpoint rows. Oversized/non-byte input fails before hashing/publication with bounded parser issues.

SQLite schema version two adds one STRICT `import_previews` table alongside the unchanged checkpoint table. Existing version-one schema must match exactly before a transactional upgrade; unknown/foreign/altered stores fail. Existing file name, checkpoint row storage version and canonical TEXT encoding remain unchanged. The single upgrade has rollback and abrupt-process-exit checks; this does not establish general backup/restore or arbitrary migrations.

Initial focused tests reached all cases without assertion failures, but pytest exited unsuccessfully at cache finalization because managed filesystem access denied the normal `.pytest_cache` location. That attempt is not reported as a passing run. Initial strict mypy found two redundant casts and one untyped lambda-call collection; corrected before required verification. Same-agent review added a guard/test preventing new staging from silently recreating missing evidence already required by an immutable checkpoint.
