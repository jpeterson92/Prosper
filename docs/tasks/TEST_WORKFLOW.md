## Delivered behavior

The [PowerShell helper](../../scripts/dev.ps1) now exposes `dev` (lint/type/scoped tests/project checks), `test` (scoped tests), `docs` (document/manifest/diff checks), `check` (full lint/type/tests/project), and `checkpoint` (full checks plus isolated-wheel package qualification). Existing bootstrap/sync/package behavior remains. `-TestPath` accepts test files/node IDs, `-LastFailed` requires a reviewable explicit scope, `-Workers` defaults to `auto`, and `-Workers 0` is serial. `-ForceFull` bypasses reuse only for an explicit full checkpoint. Narrowing a full check is refused before tests begin. The helper never commits/pushes; dependency `sync` is still the existing environment-sync operation, not GitHub synchronization.

The [Python runner](../../scripts/run_tests.py) uses pinned pytest-xdist 3.8.0 and pytest-testmon 2.2.0, with execnet 2.1.2/coverage 7.17.0. They are development-only; existing dependency versions and runtime requirements do not change. [Official xdist scheduling](https://pytest-xdist.readthedocs.io/en/stable/distribution.html) and [testmon selection/datafile behavior](https://www.testmon.org/) inform the implementation. Sources are the exact installed distributions/lock, not a separately installed service. The metadata/license inventory records MIT tools and Apache-2.0 coverage. No testmon cloud option, extra server, watcher or global hook is enabled.

Automatic selection requires a successful full local baseline/database, created only by explicit `check`/`checkpoint`. Cold/stale/configuration/data/environment state stops with a useful error and leaves explicit scoped checks available. It does not quietly initialize itself by running all Prosper tests. Testmon tracks executed Python dependencies. A conservative supplementary pass covers current test files declaring subprocess/multiprocessing operations when Python inputs change; the reporting plugin excludes node IDs already run. Arbitrary indirect wrappers, unobserved native behavior and out-of-contract external inputs are not proved tracked. New such dependencies require explicit tests or supplement extension. Fixture/non-Python/configuration/interpreter/distribution changes invalidate the baseline; Markdown-only changes do not.

Full pytest reuse binds source, configuration/data, interpreter/distributions and execution settings to an existing successful full receipt and selection database. It is disabled by a later recorded failure; forced full execution is available. Affected execution carries the previous full identity rather than falsely promoting itself into a full result. Inputs changed during verification cannot advance the baseline, and mutation/interruption failures require a fresh full checkpoint before further automatic selection. Full pytest caching does not certify lint/type, package, browser, model or release evidence.

The [pytest reporting plugin](../../scripts/pytest_workflow.py) writes actual worker count, executed IDs and setup/call/teardown durations. Every phase records its command, console output, JUnit XML, wall time and input-identified summary in ignored `.local/test-workflow/runs/<id>/`. Shared baseline/testmon/last-failure state has an exclusive active-run lock. Each phase and nested pytest invocation receives fresh scratch/cache directories; runner-owned failed IDs seed the next cache. Thread/pytest overrides are local child environments: one OpenBLAS/OpenMP/MKL thread per worker prevents nested numerical thread pools competing with xdist's automatic workers. Existing inherited `PYTEST_ADDOPTS` cannot narrow the runner's full command. No cache ACL, system setting, caller environment or application numerical implementation changes.
