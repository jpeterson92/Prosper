## Behavior and authority

[Playwright configuration](../../frontend/playwright.config.mjs) now defaults to four workers and `fullyParallel: true`. Each existing browser scenario retains its runtime isolation, assertions and lifecycle/security/recovery coverage. The [frontend helper](../../scripts/frontend.ps1) adds `test`, `-TestPath` file filters, `-Grep` title regular expressions and `-Workers` (positive integer, default four). Tests-only mode uses the current build without contract generation or compilation; rebuilding after relevant UI changes remains required. This is explicit selection, not automatic change tracking. File filters are relative to `frontend/` and use Playwright's regex matching.

Full frontend `check` still runs contract drift, deliberate contract/type failures, TypeScript, production build and all browser cases. It rejects file/title filters; unrelated commands reject worker overrides; empty filters and option-shaped file filters are refused. A selection that matches zero tests fails. No retry, skipped acceptance case, timeout increase or shared application runtime is introduced.

The new [combined helper](../../scripts/checkpoint.ps1) runs the existing Python/package checkpoint to completion, then full frontend verification. Python workers default to `auto`, browser workers to four. `-ForceFull` forwards the existing Python reuse override. Either stage's failure stops the command. It has no scoped-test arguments and does not commit, push or schedule anything. The individual Python `dev.ps1 -Command checkpoint` keeps its earlier Python/package scope. The protocol now directs full local commit/sync checks through the combined helper and forbids overlapping full Python/browser runs in separate invocations. Internal suite parallelism remains enabled. This is sequencing, not a cross-session mutex; independent conversations still need to observe the rule. Hosted CI is unchanged.

The installed Playwright CLI and its official [parallelism](https://playwright.dev/docs/test-parallel) and [CLI](https://playwright.dev/docs/test-cli) contracts informed the implementation. An actual negative selection check found that this installed CLI discards file filters after `--`, treating those arguments separately. The helper now passes validated file filters before any such separator, supplies the title as one `--grep=...` argument and rejects option-shaped file filters. The corrected wrong-file/title check fails rather than running the title from another file.
