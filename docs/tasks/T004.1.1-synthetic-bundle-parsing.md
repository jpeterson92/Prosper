## Entry point and concrete schema

`parse_bundle(raw: bytes) -> ParseResult` is the supported untrusted-input entry point. A result has either `parsed` or located `issues`, plus `further_issues` when the diagnostic cap was exceeded. A successful `ParsedBundle` contains frozen `document`, original `raw_bytes`, raw SHA-256, `canonical_bytes` and normalized SHA-256; its status is always `parsed_unvalidated`. There is no committable/planning-ready property. Direct construction or `model_validate` on the internal record models is not the bounded decoder entry point.

The document has required closed `metadata`, `accounts`, `securities`, `positions`, `lots`, `cash`, `activity`, `quotes` and `coverage` fields. The eight record families are immutable tuples; all models are strict, frozen and reject extra fields. All records have `id`; positions additionally reject duplicate `(account_id, security_id, checkpoint_id)` identities, cash duplicate `(account_id, currency, checkpoint_id)` identities. Each other family's IDs are unique within that family. Activity `id` is its stable source event identity; `source_ref` is retained provenance, not a fallback deduplication key. Well-formed dangling references are intentionally not resolved here.

## Decoder, resource limits and identity

The decoder checks byte size and UTF-8/BOM before JSON, then scans container depth with quoted/escaped strings respected. JSON objects first become ordered pairs so duplicate keys, including escaped-equivalent keys, cannot be overwritten. JSON numeric tokens remain inert token objects until strict field rejection; no int/float conversion occurs. Nonfinite JSON extensions are located and rejected. After resource/duplicate/Unicode checks, typed validation runs per bounded record; it stops after the diagnostic cap is exceeded instead of constructing one 10,000-row schema error tree.

Actual engineering limits: 2 MiB payload; container depth 16 (root counts as 1); 10,000 total top-level records; 10,000 elements per array; 1,000 members per object; ID length 128 and other string length 4,096; at most 100 returned issues with an explicit further-issues flag. The 1,000-member object guard refines the planning bounds to constrain pathological schema-error expansion. All limits have exact-limit/over-limit tests; reaching a resource limit does not make an otherwise malformed schema valid. These are unmeasured engineering capability limits, not investor/financial defaults or the target portfolio scale qualification.

Issues contain stable codes and field/index paths, with no supplied value or traceback. Invalid-UTF-8 offsets count bytes; JSON syntax/depth offsets count decoded characters. Invalid Unicode scalar strings/keys cannot reach fingerprint encoding. Imported formula/script/path/URL-like text remains inert; the parser performs no file dereference, network call, evaluation or logging. Later UI/export escaping is outside this child.

Normalized bytes are UTF-8 JSON for an envelope containing `canonicalization_version=canonical-json-v1` and the entire typed document: sorted object keys, compact separators, non-ASCII preserved, nonfinite output forbidden. Each top-level record family sorts by unique `id`; included activity references sort as a unique set. Other nested arrays (notes, lot links and coverage labels) retain input order. Exact values serialize canonically; explicit basis quantum, unknown reasons, source IDs, versions and all meaningful fields remain included. Original numeric spellings/inferred source precision remain in the document's ExactValue objects and raw evidence, not in normalized bytes. Thus `1000` and `1000.00` can share normalized identity when explicit quantum/other facts agree, while original evidence and raw hashes remain distinct. There is no local observation clock in this identity; authoritative recorded/ingested times remain later persistence work.

The hashes are identity evidence, not authenticity, import idempotency, correction acceptance or financial validation. Distinct activity IDs remain distinct even if other fields match. In-memory result/models/facts/exact values are frozen and record arrays are tuples; exported model dictionaries and caller fixture dictionaries cannot mutate the receipt. Deliberate Python private/reflection bypass is not an authenticity/security boundary.
