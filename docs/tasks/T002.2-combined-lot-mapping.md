## Delivered boundary

`prosper.fidelity_lots.inspect_combined_lots(raw)` accepts caller-declared fictional combined-file bytes. It performs no file reads, original-export lookups, account access, state mutation, persistence, logging, HTTP or browser operations. The caller assertion is not a detector of investor information. The source shape follows the owner's approved stock extrapolation from the supplied combined format; no private example is reread in this invocation and no native stock export is qualified.

The frozen `LotInspection` retains a raw-byte SHA-256, exact header, bounded parsed records, original cell strings, source logical-record references, located issues and source observations. Numeric projections use existing bounded `ExactValue`; acquisition dates use an explicit English month map and calendar validation, independent of host locale. Percent values are percentage points, not fractional rates. Source text remains separate from the normalized decimal/date spelling. The inspector neither derives a price from value/quantity nor replaces supplied total basis with rounded average basis. Term, account labels, descriptions and download timestamps remain uninterpreted source strings.

The result is `observed_unqualified` or `invalid`. Both `planning_ready` and `canonical_checkpoint_ready` are always false. `Observed.value=None` carries a reason for blank or `--` cells; unsupported numeric/date syntax is an issue with its logical record/column, never zero or a guessed date. Issue/default dataclass representations omit source cells and observed values. Consumers still hold sensitive source records if they misuse the fictional boundary; do not log or share them.

The closed header is versioned as `fidelity-combined-lots-observation-v1`. UTF-8 with optional BOM and LF/CRLF transport are accepted without changing raw identity; the exact 15-column order is required. Work is bounded by 2 MiB, 10,000 data records, 4096 characters per data field and 100 retained issues. Overflow reports truncation/further-issues explicitly. The caller retains original bytes for malformed/truncated input; partial records never imply complete inspection. Header-only input is explicitly refused as `no_lot_records`, rather than proof of an empty portfolio.

Source-file names must be basenames, source record references positive integers, and metadata present. Repeating an account/file/record reference is refused as duplicate or conflicting evidence while preserving parsed rows. Reusing one source basename with inconsistent account/security/collection metadata is also refused. Identical lot values at different source records remain separate. These checks establish within-file coherence only: the source downloads have not been opened or independently verified, and file-local row references are not durable lot IDs across downloads.

## Field-to-canonical contract

This table maps source observations to the adopted [conceptual data contracts](../architecture/DATA_CONTRACTS.md) and actual `bundle_schema` responsibilities. It is not an emitted `synthetic-checkpoint-v1` document. Required source facts are absent, so constructing that document by inventing cutoff/roles/IDs would violate the existing checkpoint boundary. No canonical schema or validation rule is weakened.

| Combined field | Retained/projected observation | Canonical destination and condition |
| --- | --- | --- |
| Account number | Exact source text, including leading zeros | Account source mapping only after explicit private identity/profile binding. No generated traded-account role, ownership or tax type. |
| Account name | Uninterpreted exact label | Candidate account alias. `IRA` or `Taxable` text does not establish classification/relationship. |
| Symbol | Uninterpreted exact symbol | Security ticker display; separate qualified identity/share-class mapping still required. |
| Security description | Exact quoted text, including commas/newlines/HTML-like text | Source evidence only; no inferred domestic common-stock or supported tax classification. |
| Source file | Basename assertion retained | Import-batch/source provenance. Neither filename nor existence is verified by this bytes-only inspector. |
| Source CSV row | Positive logical-record reference and original spelling | File-local source locator scoped to this evidence. Never a durable broker lot ID or overlapping-download dedup key. |
| Source download date | Exact opaque collection text | Collection metadata, never snapshot effective cutoff, inclusion proof or quote time. |
| Acquired | Source string plus calendar-date projection or explicit unknown | Candidate `Lot.acquired` only with qualified source semantics. Does not supply carried holding-period evidence or prove transferred original dates. |
| Term | Uninterpreted exact label | Candidate holding evidence for review; no conversion into legally qualified short/long status. |
| $ Total gain/loss | Exact signed observed amount | Display diagnostic only. Not realized P&L, tax loss, order economics or basis reconstruction. |
| % Total gain/loss | Exact signed display percentage points | Display diagnostic only; not a risk/return rate or independent financial validation. |
| Current value | Exact nonnegative observed amount | Source valuation observation. No synthesized quote price/time or independent position snapshot. |
| Quantity | Exact nonnegative observed quantity and quantum | Candidate remaining lot quantity after identity/cutoff/source qualification. Fractions stay intact; no order quantities are generated. |
| Average cost basis | Exact nonnegative display amount and quantum | Retain display evidence; never multiply a rounded average to overwrite supplied total basis. |
| Cost basis total | Exact nonnegative **reported** amount and quantum, or unknown | Candidate `Lot.basis` and `basis_quantum` only after currency and adjustment/source qualification. The inspector does not assert that all required tax adjustments are included. |

The dollar sign is parsed as display syntax, not proof of USD. `Account`, `Security`, `Position`, `Cash`, `Activity`, `Quote` and `Coverage` records need facts this file does not carry. Independent position quantities cannot be manufactured by summing lots and then treated as reconciliation evidence. Missing cash cannot become zero. An absent activity array cannot become complete household history. Unknown source identity/cutoff prevents authoritative checkpoint emission regardless of known observed quantities.
