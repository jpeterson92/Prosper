# Collecting Fidelity lot files for Prosper

Fidelity is the initial broker test case selected by the owner. For the **retail Fidelity positions-page workflow reported by the owner on October 23, 2026**, there is no single direct bulk download of all individual lots across accounts. The documented workaround is to let a user-authorized browser-capable assistant collect the available per-position lot CSV downloads and consolidate them with a deterministic CSV parser/writer. The owner supplied one resulting combined example and a reusable prompt. This does not assert the absence of every export facility across all Fidelity products, advisor channels or future interfaces.

The public [Trader+ positions guide](https://www.fidelity.com/trading/trader-desktop-user-guide/positions) documents position CSV output; it does not establish that the positions summary contains all individual lots. The [public evidence report](../tasks/T002.1-public-broker-evidence.md) retains the separate lot/history/cash/confirmation qualification gaps. The supplied example improves structural evidence for the combined output only.

## Procedure for a future user

1. Choose the assistant/provider and understand that the account information it reads will be available to that service. Sign in to Fidelity yourself in the supported browser and open the positions page. Never give a prompt your password, MFA code or browser credentials. The user must explicitly authorize the data and assistant destination for that collection run.
2. Invoke the [copyable collection prompt](FIDELITY_TAX_LOT_EXPORT_PROMPT.md). Its authorization language applies only when the user deliberately submits it for that run. Agents merely reading the repository or template must not execute it or treat it as standing account access.
3. The assistant inventories the account/position scope, uses the site's available lot-download controls for each position, and records omissions or unavailable exports. It retains original files and an account/security/file manifest outside the source repository. If login, MFA, CAPTCHA, access restrictions or an unfamiliar schema prevents progress, the user handles the interaction or the run reports the gap. Do not bypass access controls, use undocumented endpoints or assume automation is permitted by a template.
4. A normal CSV parser/writer builds the combined output. The LLM coordinates collection and explains issues; it must not transcribe, invent, round, recompute or estimate financial fields. Original download values are copied as text, with provenance. The procedure performs no trades, settings changes, basis corrections or account mutations.
5. Before calling a collection complete, reconcile the page inventory against the manifest, parse every included source, compare every eight-field lot row with the combined output, verify metadata and source-record references, and verify that original files remain unchanged. Identical-looking lots remain separate. Conflicting repeats or omitted/unavailable positions stay explicit. The current task did not rerun that browser collection or verify its original downloads.
6. Keep the real combined file, source downloads and private manifest outside Git/source, logs, demos and shared reports. Supply fictional or field-only examples for development. The current local browser accepts the combined CSV with account/date opening facts or an optional reviewed context document. Use the [fictional walkthrough](../../examples/synthetic/fidelity/README.md); this local adapter does not qualify real sources or authorize account access.

The prompt's consolidation contract has seven metadata fields followed by eight unchanged lot fields:

```csv
Account number,Account name,Symbol,Security description,Source file,Source CSV row,Source download date,Acquired,Term,$ Total gain/loss,% Total gain/loss,Current value,Quantity,Average cost basis,Cost basis total
```

`Source CSV row` counts parsed records in the original source, including preamble and blanks, rather than physical lines. A quoted multiline field is one record. Preserve account identifiers as text, source basenames, currency/percentage signs, commas, precision, blanks and annotations. `Source download date` retains the source timestamp after removal of the specified prefix; neither filename date nor download time proves the portfolio cutoff.

## Current lot workflow

Start the protected local browser in a fresh local workspace, then load `combined-stocks.csv` and `current-context.json` from the fictional fixture guide. The context binds the combined file checksum, selected taxable account, other account roles, canonical identities/classes, USD and actual source cutoff to attributable assertions. Review the preview and unknowns before selecting it. Source download dates and account labels supply none of those facts automatically. Original combined bytes and every source-row disposition remain retained; original per-position downloads are not certified by this adapter.

Load `current-lot-settings.json`, review marks and explicit maximum ages, isolated selling fee/discount, selected additional cash, funding and coverage. Save reviewed settings, then save lot diagnostics. Optional whole-share portions use the displayed file-local lot IDs; optional replacement IDs request screening only. With no explicit portions each row is an isolated inspection, not a simultaneous sell list. Whole shares never consume a fractional remainder. Loss uses supplied total basis pro rata, with price/basis loss separate from indicative net-proceeds P&L. Displayed source gain and rounded average basis never become reference marks or reconstructed basis.

Known same-security household/IRA acquisitions and prior loss/unknown-P&L sales are screened on both inclusive 30-day sides, alongside attributable supplied relationships and manual restrictions. Missing history retains coverage/future-activity warnings. A replacement import or omitted manual entry cannot erase retained imported conflicts. Unknown identity/date/scope, basis disputes and unbounded events block affected diagnostics explicitly. This conservative product screen does not perform tax-return share matching, adjust basis, calculate deductible loss or establish that different identities are legally distinct.

Save/reopen and current backup/restore preserve the original inputs/output and required source bytes. A lost settings/result response retries its original command; later inputs invalidate the current pointer without recalculation of historical results. No optimizer, broker order, lot-selection guarantee, live mark acquisition or financial-use acceptance is established.
